# CLI and Linux System Mastery

A backend engineer spends a significant amount of time in the terminal. Mastering these tools changes you from someone who relies on slow GUIs to someone who can instantly slice through gigabytes of logs and debug misconfigured servers.

## 1. Text Processing Core Utilities

The Unix philosophy is small programs that do one thing well, chained together with pipes (`|`).

- **`grep`**: Search for patterns.
  ```bash
  grep -ri "error" /var/log/          # Search recursively, case-insensitive
  grep -v "DEBUG" app.log             # Invert match (ignore lines with DEBUG)
  ```
- **`find`**: Search for files.
  ```bash
  find . -name "*.log" -mtime +7      # Find log files older than 7 days
  ```
- **`xargs`**: Pass output of one command as arguments to another.
  ```bash
  # Delete all log files older than 7 days
  find . -name "*.log" -mtime +7 | xargs rm
  ```
- **`awk`**: Columnar text processing.
  ```bash
  # Print the 4th and 5th columns of a space-separated log file
  cat access.log | awk '{print $4, $5}'
  ```
- **`sed`**: Stream editor (find and replace).
  ```bash
  # Replace "http" with "https" in all config files
  sed -i 's/http/https/g' config.yaml
  ```

## 2. API Debugging: `curl` and `jq`

- **`curl`**: The universal HTTP client.
  ```bash
  # Send a POST request with JSON and headers
  curl -X POST https://api.example.com/v1/users \
       -H "Authorization: Bearer mytoken" \
       -H "Content-Type: application/json" \
       -d '{"name": "Alice"}'
  
  # -i shows headers, -v shows the full TLS handshake
  curl -i https://example.com
  ```
- **`jq`**: Command-line JSON processor.
  ```bash
  # Pretty-print JSON
  curl -s https://api.github.com/repos/torvalds/linux | jq .
  
  # Extract specific nested fields
  curl -s https://api.example.com/users | jq '.[].email'
  ```

## 3. Linux Networking

When a service "can't connect," you need to prove whether it's an application issue, a firewall issue, or a routing issue.

- **`ss` (replaces `netstat`)**: See open sockets.
  ```bash
  # Show all listening TCP ports and the process using them
  ss -tulpn
  ```
- **`telnet` or `nc` (netcat)**: Test basic TCP connectivity.
  ```bash
  # Does a firewall block us from hitting the DB on port 5432?
  nc -vz db.example.com 5432
  ```
- **`tcpdump`**: Packet sniffer. The ultimate source of truth.
  ```bash
  # See all HTTP traffic going in and out of eth0
  tcpdump -i eth0 port 80 -A
  ```
- **`iptables`**: The Linux kernel firewall.
  ```bash
  # Block all incoming traffic from a specific bad IP
  iptables -A INPUT -s 192.168.1.50 -j DROP
  ```

## 4. Process Management

In modern infrastructure, Kubernetes handles process management. But on raw VMs (like EC2 instances), you need a process manager to restart your app if it crashes and start it on boot.

**Systemd** is the standard init system for modern Linux. You write a Unit file (`/etc/systemd/system/myapp.service`):

```ini
[Unit]
Description=My Backend App
After=network.target

[Service]
ExecStart=/opt/myapp/server
Restart=always
User=appuser
Environment="DB_URL=postgres://..."

[Install]
WantedBy=multi-user.target
```

Manage it with `systemctl`:
```bash
sudo systemctl daemon-reload
sudo systemctl enable myapp    # Start on boot
sudo systemctl start myapp
sudo systemctl status myapp
# Read logs generated by the app via the systemd journal
journalctl -u myapp -f
```
