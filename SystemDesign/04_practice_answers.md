# System Design Reference Answers

One condensed answer per prompt in [System Design Practice Prompts](03_practice_prompts.md), 01 to 41. Each is a summary of the full solution in `solutions/`; open that for estimates, diagrams, follow-ups and the build exercise. Use the same lens for every design: authoritative data, access patterns, idempotency, ordering scope, bounded failure behavior, observability, security, and an explicit scale trigger.

## 01 URL Shortener
The code-to-destination mapping is authoritative durable data keyed by `code`; click analytics are derived and asynchronous. Generate random 7-character base62 codes and insert under a unique constraint (retry on the rare collision); custom aliases rely on the same unique insert, never check-then-insert. Creation takes an idempotency key. Redirect returns `302` so destination changes and disables take effect; `301` is cached by clients and intermediaries. Serve redirects from an edge/redirect cache sized to the database's miss budget (Zipf popularity makes ~25 GB cover ~80%), and emit click events to a log off the request path. Switch to pre-allocated counter ranges with a keyed permutation when creation goes multi-region active-active. Measure redirect p99, cache hit ratio, create error/collision retries, analytics lag, abuse reports. Build create/redirect with a unique-insert race test.

## 02 Rate Limiter
Use an atomic token bucket keyed by policy and actor in a shared in-memory store: `tenant:user:route`. Capacity permits burst; steady refill sets average rate. Layer global safety, tenant-plan, and expensive-route quotas. Fixed windows are simpler but burst at boundaries; sliding logs are exact but costly. Fail closed for payments/abuse-sensitive work and use bounded local/fail-open policy only for low-risk browsing. Measure rejection rate, limiter p99/error, hot keys, and protected-backend saturation. Build it with atomic refill/spend and simulate concurrent requests/outage.

## 03 Pastebin
Keep metadata/ACL/expiry in relational storage and body in object storage for large snippets; CDN/cache public immutable reads. Opaque IDs help unlisted links but private data still needs resource authorization. Expiry status is enforced on read before asynchronous cleanup. Cache public content with TTL/purge rules; cache outage falls back to source. Avoid database BLOBs by default for large bodies, but small snippets may fit. Measure read p99, hit ratio, expiry denial, storage growth, abuse reports. Build create/read/expiry with signed private access.

## 04 Notification Platform
Persist notification intent then route through preference/quiet-hour decision into separate priority/channel queues. Channel workers call providers; verified provider webhooks update idempotent delivery state. Key intent by event/user/template/channel to deduplicate retries. Separate password-reset from marketing so bulk work cannot starve critical work. Do not send inline from product APIs: provider latency/outage becomes product outage. Measure intent-to-delivery latency, provider error/bounce, queue age, DLQ, opt-out compliance. Build one channel plus preference and retry policy.

## 05 Photo Pipeline
Authorize resumable direct multipart upload to object storage; metadata DB tracks `UPLOADING → PROCESSING → READY/FAILED/DELETED`; workers scan and create idempotent derivative versions. Keep original checksum/owner/visibility/object keys in metadata. Do not proxy 50 MB through app servers or process synchronously. Deletion first denies metadata/access and invalidates CDN, then deletes all variants asynchronously. Measure upload success, processing lag, failure, orphan objects, CDN hit. Build signed upload plus one thumbnail worker.

## 06 Chat
WebSocket gateways provide live transport; durable message store/log provides truth and offline replay. Assign a server sequence per conversation after append; client message ID makes send idempotent. Recipient cursor supports delivered/read/offline sync. Presence is TTL-based approximate state, never delivery truth. Global ordering is unnecessary; 100k-member groups persist once and fan out only to active clients/notification policy. Measure durable append/fanout lag, reconnect sync, hot-room partitions. Build one room, reconnect cursor, duplicate send test.

## 07 News Feed
Posts are truth and feeds are derived projections. Push fanout for normal accounts gives fast reads; pull/merge celebrity timelines to avoid 50M writes; hybrid selects by follower threshold. Store feed references, hydrate current post/visibility, and cursor paginate. Search/cache cannot be source because deletes/privacy must propagate. State 30-second freshness rather than false strict consistency. Measure post-to-feed lag, fanout backlog, feed p99, delete propagation, hot author impact. Build chronological feed before ranking.

## 08 Checkout
One transaction creates idempotent order, conditional inventory hold, and outbox event. A workflow performs payment/fulfillment with guarded state transitions; provider event ID deduplicates callbacks. Reconciliation compares external settlement to internal immutable records. Do not call payment inside inventory transaction; locks and remote failure create outage. Do not decrement inventory after payment without reservation. Measure hold expiry, duplicate checkout, payment lag/error, mismatch, oversell invariant. Build an order state machine and simulated provider retries.

## 09 Search and Autocomplete
Catalog DB/outbox drives a versioned derived search index; query applies tenant/visibility filters and ranking. Autocomplete is a separate bounded prefix path with debounce/cache. Reindex into a new index then atomically swap alias. Search is not authoritative: index lag and deletion repair exist; publish a five-minute freshness target. Avoid relational wildcard scans at scale. Measure index lag, query p99, zero-result/relevance quality, authorization leak tests. Build an indexer and blue/green reindex simulation.

## 10 Seat Reservation
Authoritative seat row atomically transitions `AVAILABLE → HELD(hold, expiry) → SOLD`; only current unexpired hold can confirm. Waiting room issues signed admission tokens and limits safe arrival rate. Payment is a saga; expiry/release is idempotent. Never check then update availability, and never use cache as sale arbiter. Measure hold conflicts, lock waits, expiry, payment-before-expiry, double-sell invariant. Build conditional SQL hold and concurrent race test.

## 11 Web Crawler
Normalize URLs then deduplicate URL hash; host-partitioned frontier applies robots and per-host token bucket; fetchers store content hash and extract links. Schedule recrawls by change/importance/error backoff. One global queue violates politeness and lets a host dominate. URL and content dedupe solve different problems. Measure frontier age, host error, politeness violation, dedupe ratio, bytes. Build a local host-aware frontier first.

## 12 Workflow Scheduler
Persist workflow/job state, retry policy, timer, and lease/fencing token. Workers claim ready work under a lease; only current lease can complete; expiry enables recovery. Durable timers replace sleeping threads; human approval is a persisted wait. Exactly-once execution is impossible around uncertain side effects, so activities need idempotency. Measure schedule lateness, task age, retry/DLQ, lease reclaim, workflow age. Build a two-step workflow with worker crash simulation.

## 13 Metrics Platform
Ingest validates tenant/schema/quota, appends to WAL/stream and write-optimized time-series blocks partitioned by tenant/time/series. Retain high-resolution recent data, compact/downsample older data, and evaluate alert rules. Cap active series; labels like user/request ID create a cardinality incident. Metrics are not exact billing records. Measure accepted/rejected samples, active series, compaction lag, query p99, alert delay. Build a counter/histogram ingest and tenant cardinality guard.

## 14 Logging Platform
Agents batch/spool structured logs to durable ingest; index common fields/time partitions and retrieve chunks for bounded query. Redact sensitive fields before/at ingest; enforce tenant query ACL/audit and retention lifecycle. Logging must not synchronously block product requests. Bounded local disk buffer sheds under backend outage. Do not index every arbitrary field forever. Measure loss/buffer fullness, index lag, query cost, redaction failures. Build structured logs correlated with trace ID.

## 15 Drive
Object storage holds immutable file versions; relational metadata represents current version, folders, ACL, trash, and change cursor. Direct resumable upload reduces API bandwidth; outbox powers sync/index/scanning. Offline clients sync from cursor and create conflict copy/domain merge rather than silent overwrite. Object key is not permission. Measure sync success, conflict rate, orphan objects, ACL denial, delete propagation. Build versioned metadata and two-client conflict test.

## 16 Video on Demand
Source object triggers asynchronous validation/transcoding into bitrate/resolution segments and manifest; CDN serves signed/authorized manifest and immutable segments. Player adapts bitrate to bandwidth/buffer. Playback analytics is asynchronous. One source file through app servers cannot provide global adaptive delivery. Measure start time, rebuffer ratio, encoding lag/failure, CDN hit, origin egress, entitlement denial. Build one source-to-HLS-like derivative flow conceptually.

## 17 Payment Ledger
Post immutable balanced double-entry journal lines in one transaction; balance is derived/materialized and checked. Idempotency/provider reference prevents duplicate postings; corrections are reversing entries, not edits. Spend authorization uses strong transactional available-balance check; reconciliation imports external settlement as evidence/correction. A mutable balance field alone loses audit and recovery. Measure balance invariant, duplicate rejection, reconciliation mismatch, posting p99. Build journal plus replayed transfer test.

## 18 Distributed Cache
Client routes keys through consistent-hash ring with virtual nodes; TTL/eviction bound memory; short client deadline and coalesced source fallback prevent outage cascade. Replication can improve reads but complicates invalidation. Hot keys need near-cache/replicas/prewarm/coalescing; uniform TTL causes expiry herd. Cache is never truth. Measure hit/eviction/memory, skew, node error, source fallback, rebalance movement. Build a simple ring and node-loss simulation.

## 19 Feature Flags
Audited control plane stores typed/versioned rules; distribution pushes/polls snapshots to SDK local cache; request evaluation is local and has visible staleness. Flags require owner/default/expiry and kill-switch policy. Central request-time evaluation makes every request depend on control plane. Targeting uses validated context and RBAC-protected change audit. Measure propagation/staleness, evaluation errors/latency, stale flags. Build local evaluator with percentage hash and snapshot fallback.

## 20 Ride Dispatch
Location stream updates an ephemeral geo-cell index; trip DB holds durable request/assignment/payment state. Dispatch queries adjacent cells, ranks candidates, offers a short lease, and conditionally assigns first accept. Location is approximate and TTL’d; assignment is strongly guarded. Raw full-table geo scans do not scale; location store should not arbitrate trip state. Measure location freshness, candidate p99, offer races, assignment time, hot cells. Build cell-neighbor lookup and assignment race test.

## 21 Multi-Tenant API Gateway
Gateway handles TLS, authentication validation, route/version policy, quota/body/deadline limits, tracing, and upstream routing; services re-authorize business/resource access and enforce tenant-scoped queries. Cache keys/config safely and define identity-control-plane outage behavior. Do not put all business logic in gateway or trust a caller-provided tenant header. Measure auth/quotas, upstream p99/error, tenant saturation, config staleness. Build route-level token bucket and trace propagation.

## 22 Unique ID Generator
Generate IDs locally with a Snowflake layout re-split for the fleet: sign bit, 41 bits of milliseconds since a custom epoch (2020 lasts to about 2089), 3 datacenter bits, 12 worker bits, 7 sequence bits. Worker IDs come from a lease in etcd/ZooKeeper once per process, never from hostnames or config, so no coordination sits on the per-ID path; a pooled ID service handing out batches covers languages without the library. The contract is unique and k-sortable, not strictly monotonic; strict global order would need a consensus sequencer and lose partition availability. Guard the clock with `lastTs`: wait out a small rollback, refuse and go unhealthy on a large one. Serialise IDs as strings in JSON because values exceed 2^53. Measure IDs/s per worker, clock offset and regressions, sequence-exhaustion waits, lease failures, downstream unique-key violations. Build a CAS generator with a duplicate test under 8 threads and clock-rollback injection.

## 23 Distributed Key-Value Store
Leaderless Dynamo-style ring: consistent hashing with about 128 virtual nodes per server, `N = 3` replicas in three zones, any node coordinates, and per-request `R`/`W` trade latency for consistency. `R + W > N` gives read-your-writes in the common case, not linearizability. "Survive any two failures" needs three durable copies at ack (`W = 3` with sloppy-quorum stand-ins, or `N = 5, W = 3`), priced explicitly. Version vectors detect concurrent writes and return siblings plus a context for the client to merge; wall-clock last-writer-wins only for idempotent overwrites. Hinted handoff covers short outages, read repair and Merkle-tree anti-entropy fix the rest, and tombstones outlive the repair interval so deletes do not resurrect. Gossip marks suspicion without removing nodes. Size from the max of storage- and throughput-bound node counts. Measure latency by consistency level, hint queue, repair bytes, tombstones per read, sibling counts. Build a 3-node simulation with a partition, siblings and a merge.

## 24 Collaborative Document Editor
Clients apply edits locally, then send batched operations against a base revision over WebSockets. Each open document is owned by one session server (consistent hash on `doc_id` plus a lease); it transforms ops with OT, appends to a durable per-document op log with a conditional `revision = last + 1` (which fences a stale owner), acks, then broadcasts. Periodic snapshots plus the log rebuild state and power history; restore and undo are new inverse ops, never rewinds. `op_id` makes resends idempotent after reconnect; offline edits rebase on reconnect. Check permission per op against a cached ACL version and drop sockets on revoke. Cursors and presence are ephemeral and never stored. One owner caps a hot document's throughput; move to a CRDT or read-only broadcast for thousands of editors. Measure op round trip, broadcast lag, snapshot age, resync rate, convergence checksums. Build OT with two clients and fuzz convergence.

## 25 Web Search Engine
Three decoupled systems joined by durable storage. The crawler runs a per-host politeness frontier with cached robots.txt, prioritises by importance and change rate, and deduplicates URLs and content (hash for exact, SimHash for near). Indexers build document-sharded, immutable, versioned inverted-index shards in tiers: a small fresh tier rebuilt in minutes and a large base tier in batch, canaried and switched atomically. Serving fans a query from root to thousands of leaves with hard deadlines, hedged requests and partial results; leaves score cheaply, the root merges and runs a learned ranker on about 1,000 candidates, then builds snippets. A serving-time suppression list handles takedowns immediately. Do not shard by term: common words become hot shards and joins. Measure per-stage p99, hedge rate, shard coverage per query, index age per tier, crawl politeness, and quality metrics per index version. Build BM25 over 8 shards with hedging.

## 26 Nearby Places
The place store (sharded by `place_id`) is truth; searches never touch it. A CDC-fed indexer maintains an in-memory S2 (or geohash/quadtree) cell index sharded geographically, with each region also holding its neighbours for border queries. Search computes the cell covering for the radius or viewport, caps candidates per cell by static score in dense areas, then ranks by distance decay, rating, popularity and open-now. Cache results by rounded cell and radius bucket, not exact coordinates, and cache place details with change-event invalidation. Querying only the user's cell misses places across the edge; a lat/lng bounding box on a B-tree scans a strip. Writes are rare, so async indexing with minutes of freshness is fine; moving objects would need a mutable grid instead. Measure p99 by city tier, candidates scanned, cache hit rate, index age, empty-result rate. Build geohash and S2 indexes over clustered data and compare.

## 27 Ad Click Aggregation
Click servers append to a durable log partitioned by `ad_id` (buffering locally so the redirect never blocks). Two paths with two contracts: a stream processor aggregates event-time one-minute windows with watermarks and allowed lateness into a real-time OLAP store and budget-pacing counters (approximate, seconds to a minute), while the raw log is archived immutably and a batch job deduplicates globally, filters fraud and produces exact, reproducible hourly billing. Sinks upsert absolute counts keyed by `(ad_id, window)` so replays are idempotent; salt hot ads and sum. Clamp client timestamps before they drive watermarks. Reconciliation compares stream and batch; bugs are fixed by recomputing from the archive. Measure event-to-dashboard lag, watermark delay, late/dropped events, stream-vs-batch discrepancy, pacing overspend. Build event-time windows with a crash and checkpoint restart that still matches batch totals.

## 28 Top-K Trending
Filter abuse first, partition events by `item_id`, and have each counter worker keep a count-min sketch plus a candidate heap (about 10 × K) per slice per minute bucket. A merger sums the last N buckets (add newest, subtract oldest) and merges candidate sets across partitions to publish top-K lists per window, region and category with `generated_at`; the API serves them from cache. Error is bounded relative to total events and heavy hitters are never missed; exact per-item maps for every slice cost far too much memory. Rank by growth over a baseline with a floor, not raw counts, so "trending" is not "always popular". Late events land in their bucket if still in the window; a daily exact batch job checks overlap. Measure ingest lag, sketch saturation, approximate-vs-exact overlap, list churn, API p99. Build sketches over a Zipf stream and compare against exact counts.

## 29 Real-Time Leaderboard
The score database is truth (idempotent by `match_id`); an outbox feeds updaters that maintain Redis sorted sets as a rebuildable projection. Encode the tie-break in the score, `score × 2^22 + (SEASON_END − achieved_at)`, and `ZADD` the recomputed composite rather than `ZINCRBY`. A hybrid layout gives exact answers where they matter: a global top set for the top 100 and near-top, 16 hash-sharded sets for a player's score and neighbours, and a score histogram with cached cumulative counts for approximate long-tail rank ("~1.2M" or "top 12%"). Exact global rank for everyone would mean one giant set or fan-out to every shard per read. Seasons are new keys, not rewrites; friend boards are small per-user queries. Accept only server-signed results. Measure score-to-rank lag, shard p99, histogram error, memory, rebuild time. Build the top set, shards and histogram over 10M players.

## 30 LLM Assistant Feature
An AI gateway authenticates, checks org enablement and enforces request and token quotas before any GPU work. An orchestrator builds versioned prompts, retrieves a few ACL-filtered messages from a per-user hybrid index (checked against the source of truth, never whole mailboxes), marks email content as untrusted data, and routes most traffic to a small model with escalation to a large one. Model pools use continuous batching with paged KV cache and prefix caching of shared templates; size prefill and decode, bound queues by time-to-first-token, and cancel generation on disconnect. Input and output guards block injection, policy violations and PII; responses stream over SSE with citations. Caches are per user and thread version, never shared semantically. Measure TTFT, tokens/s, queue time, GPU utilisation, prefix-cache hit, cost per request, guard blocks, eval quality. Build a vLLM-backed stack with quotas and routing, then load-test.

## 31 Distributed Message Queue
A partitioned, replicated, append-only log with consumer-managed offsets. Keys hash to partitions for per-key order; RF 3 across zones, `acks=all` and `min.insync.replicas=2` so a zone loss loses nothing and publishing continues. Brokers write sequentially and serve caught-up consumers from page cache; a controller quorum holds metadata and elects leaders from the ISR. Consumer groups assign partitions to members; at-least-once is process-then-commit, and exactly-once effect needs an idempotent sink or offsets stored with the result. Retry tiers, a DLQ and a timer service for delays sit on top so a poison message does not stall a partition. Size partitions from consumer throughput (a one-way door for keyed order) and brokers from the max of disk, network and zone-loss headroom; tenant quotas stop noisy neighbours. Page on any partition under min ISR. Build an in-process broker with ISR, idempotent producer, commits and DLQ.

## 32 Ranked Home Feed
A cascade sized by budget: several retrievers (followed accounts, ANN embeddings, trending) with per-source quotas produce about 3,000 candidates, hard filters remove blocked, muted, policy-violating and seen posts (Bloom filter), a light ranker cuts to about 300, a heavy multi-task model scores about 100 on roughly 300 features, and a re-ranker applies diversity and a budgeted exploration slice. Value is a policy-weighted sum of predicted actions, not CTR alone. The top 50 are frozen in a session snapshot for 30 minutes so pages never repeat or skip. A feature store serves batch and real-time counters within two minutes; every impression is logged with features as served for leak-free training. Deadlines drive a tested degradation ladder (`degraded_rung` in the response), not errors. Page on p99 over 400 ms or more than 1% degraded loads. Build a cascade simulator with deadlines and snapshots.

## 33 Live Streaming and Comments
Ingest RTMP/SRT/WebRTC at regional ingest servers, transcode an ABR ladder only for streams with audiences (passthrough the rest, hot standby for the biggest), and package CMAF segments and LL-HLS parts with deterministic names so active-active packagers are interchangeable. The CDN (multi-CDN with headroom for the marquee event) carries viewers; the origin only feeds shields. Low latency costs requests and buffer, so gate that tier. Chat is durable for storage but sampled for display: a single-writer sequencer per room with fencing epochs publishes one feed capped by reading speed (about 5 msgs/s) that is identical for everyone; reactions are aggregated, not sampled; the client releases comments by stream timestamp so chat never spoils video. Moderation deletes ride the same feed. Record to object storage for DVR and VOD. Page on rebuffer ratio of the largest stream. Build a fake-clock simulation of ingest, packaging and the chat sequencer.

## 34 Maps Routing and ETA
Separate topology from metric: partition the graph once per map build into a customizable multilevel overlay (CRP-style), held in RAM by continent-scale shard groups, and re-customize edge weights every minute from blended live probe speeds, time-of-day profiles and free flow. Queries run bidirectional search on the overlay in milliseconds; plain contraction hierarchies stay for static weights such as offline packs. Probes are map-matched with an HMM, aggregated anonymously per stable `segment_id`, and weighted by distinct devices against poisoning; no data falls back to the profile, never free flow. An ML model predicts the ETA residual on the chosen path. Each answer names its `build_id` and `metric_version`. Navigation re-checks every 5 s and re-routes only with a minimum saving and hysteresis. Map builds are shadow-diffed, canaried and rolled back by pointer flip. Build a grid graph with an overlay, Dijkstra and an HMM matcher.

## 35 Distributed Object Store
Split metadata from data. A sharded, strongly consistent metadata index maps `(bucket, key, version)` to chunk locations, ordered by key so `LIST` by prefix is a range scan. Data is written as immutable chunks, erasure-coded (for example 10 data + 4 parity across failure domains, about 1.4× overhead instead of 3×) with checksums; small objects are packed into larger extents. A PUT stores and fsyncs the fragments, then commits metadata, so readers never see a partial object. Durability comes from fast repair: a scrubber verifies checksums and a repair service rebuilds lost fragments with priority by how few remain; the durability math is failure rate against repair time. Deletes and overwrites write metadata tombstones, and garbage collection reclaims unreferenced chunks later. Hot prefixes need index splitting. Measure durability risk (fragments at minimum), repair backlog, GC lag, LIST and GET p99. Build an erasure-coded store with a disk-failure repair test.

## 36 Content Delivery Network
A multi-tenant reverse-proxy cache. Steering uses anycast for DNS and the general pool and DNS mapping for the heaviest zones; an L4 balancer spreads flows and servers in a POP consistent-hash each cache key to one owner, so the POP behaves as one big cache. Misses collapse into one fetch up a hierarchy (edge, regional parent, per-origin shield), keeping origin traffic near 1%. Cache keys are tenant-scoped and normalised (strip tokens, session ids, `utm_*`); `private`, `no-store` and `Set-Cookie` are never shared. Config and purges (URL, prefix, tag) are committed centrally and pushed down a relay tree; purge p99 is 5 s, and exact correctness uses versioned URLs. The data plane fails static on its last snapshot, so a control-plane outage is not a customer outage; `stale-if-error` covers origin failure. TLS certificates sit in RAM with staged renewal. Page on fast burn of cacheable success. Build a consistent-hash POP with collapsing.

## 37 Experimentation Platform
Assignment is a pure function `variant = f(config_version, unit_id)`: a salted hash per layer maps units to buckets, layers give mutual exclusion on the same parameter surface, and the SDK evaluates a pushed config snapshot locally in microseconds (relays fan it out within 60 s; SDKs keep the last snapshot if the control plane is down). Exposures are logged where the parameter is actually used, for every variant, with the config version. Streaming guardrails can auto-pause with sequential boundaries; daily batch readouts join deduplicated exposures to metrics, block on sample-ratio mismatch, use CUPED for variance and the delta method for ratio metrics, and use always-valid sequential tests so daily peeking keeps 5% false positives. Results are provisional until late data lands. Ramps only add buckets. Interference needs cluster or switchback randomization. Run a permanent A/A test. Build a hash assigner and an SRM check.

## 38 Video Conferencing
Forward, don't mix: each sender publishes three simulcast layers once to a regional SFU, and each receiver gets only the layers its tiles and downlink can use (last-N video, top-3 audio). Meetings spanning regions cascade SFUs; placement is by egress headroom, not participant count. Signaling (WebSocket) carries roster, mute and host actions as ordered, idempotent commands with `seq` resume; SFU media state is soft and rebuilt by clients after a node dies (about 4 s). Congestion control lowers layers before audio suffers; loss repair uses NACK within the deadline and FEC above about 60 ms RTT, and TURN over TCP/TLS covers UDP-blocked networks. An MCU (about 70× the CPU) is used only at a legacy dial-in edge. Webinars fan view-only attendees out through a tree of SFUs or a CDN path. The recorder is an ordinary subscriber, so its failure never touches the meeting; the E2EE mode gives up server recording, captions and the CDN webinar path. Page on join-to-first-media success.

## 39 Social Graph Service
TAO-style objects and typed, time-ordered associations stored in MySQL sharded by `id1`, behind a two-level cache (follower tiers per region, leader tier per shard) that must absorb about 99% of reads; every region holds a full copy because the graph cannot be partitioned. Lists page by `(time, id2)` and counts live in the write transaction, never `COUNT(*)`. Inverse edges span two shards, so a transactional outbox guarantees they converge. Writes go through the leader in the master region; the writer gets read-your-writes via changesets and version tokens, others see it within seconds. Hot objects are cloned across followers with client caches. Privacy (blocks, unfriends) is checked at read time on the viewer's shard so it affects cached content. Mutual friends and PYMK cap each hop, skip hubs and precompute. Page on follower hit ratio below 92%. Build an association list with an outbox and a cache.

## 40 Distributed Lock Service
A 5-replica cell (2-2-1 across zones) running Raft/Paxos over a small tree of nodes plus a session table. Clients hold sessions with KeepAlives kept in master memory, not in the log; a holder that stops renewing loses its locks within one lease (about 12 s), and a new master waits out old leases, so a short failover keeps sessions (clients enter jeopardy, then recover; expiry at about 57 s). Every grant returns a fencing token (the commit index) and the protected resource rejects older tokens; without that the lock is only an efficiency hint. Writes are linearizable; clients cache reads with master-driven invalidation and receive watches in commit order. Waiters queue and only the head is woken. It is for coarse locks, election and small config, not a database or queue. Page when no KeepAlives are served for 20 s. Build a consensus-backed lock with fencing and a paused-client test.

## 41 Email Service
Inbound SMTP servers accept mail, check SPF, DKIM and DMARC, and apply rate limits, then write to a durable queue before replying `250`, so accepted mail is never lost. A spam and malware pipeline (reputation, rules, ML classifiers, attachment scanning) labels messages before delivery. Each mailbox is stored per user: message bodies and attachments as deduplicated blobs in object storage, and per-user metadata (labels, threads, flags) in a store sharded by user id, with a per-mailbox change log whose sequence numbers act as sync cursors for IMAP, mobile and web clients. Search uses a per-user inverted index kept in step by the change log. Outbound mail is queued, DKIM-signed, sent from IP pools with warm-up and per-destination throttles, and bounces and complaints feed suppression lists to protect deliverability. Measure accept-to-inbox latency, spam false positives and negatives, sync lag, search p99, bounce and complaint rates.
