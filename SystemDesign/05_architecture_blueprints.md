# 41 System Design Architecture Blueprints

Use this alongside the questions and solutions. Each blueprint captures the missing interview detail: source of truth, contract, ordering, failure boundary, and scale trigger.

## 01 URL Shortener
**Truth:** `Link(code, destination, status)` in a durable DB. **Contract:** idempotent create; `GET /{code}` returns mutable `302`. **Flow:** cache-aside redirect; click event is asynchronous. **Hard part:** code uniqueness/custom aliases use a DB unique constraint. **Scale trigger:** redirect DB reads → CDN/cache, then partition by code hash. **Never:** make analytics synchronous or cache mappings forever.

## 02 Rate Limiter
**Truth:** atomic bucket state with refill timestamp. **Contract:** return allow/deny, remaining quota, retry-after. **Flow:** gateway spends token before expensive backend work. **Hard part:** compose global/tenant/route policies without double-counting; failure policy differs by endpoint. **Scale trigger:** shared limiter QPS → shard by actor hash and add local approximate pre-limit. **Never:** let each app instance enforce an independent global quota.

## 03 Pastebin
**Truth:** metadata/ACL/expiry DB record; body object. **Contract:** create is idempotent; read authorizes private resource before body fetch. **Flow:** public body via CDN; private through signed short-lived access. **Hard part:** expiry/abuse state overrides stale cache. **Scale trigger:** public reads → edge caching; body growth → object lifecycle tiers. **Never:** use unlisted URL as authorization.

## 04 Notification Platform
**Truth:** notification intent and delivery-attempt state. **Contract:** product emits intent, not “send exactly once.” **Flow:** preference decision → priority queue → channel worker → provider callback. **Hard part:** idempotent provider outcome and distinct urgent/bulk capacity. **Scale trigger:** campaign fanout → batch/partition recipient expansion. **Never:** let a marketing campaign share a queue/pool with password reset.

## 05 Photo Pipeline
**Truth:** media metadata/state; object store holds bytes. **Contract:** upload session is resumable/idempotent; readiness is explicit state. **Flow:** direct upload → scan → transform event → variants. **Hard part:** delete denies serving first then asynchronously removes every derivative. **Scale trigger:** transform queue backlog → autoscaled workers by format/size class. **Never:** trust filename/MIME or proxy all bytes through API.

## 06 Chat
**Truth:** durably appended per-conversation messages. **Contract:** client message ID is idempotency key; sequence cursor syncs history. **Flow:** gateway authorizes → append → online fanout/notification. **Hard part:** order only per room and make read receipts monotonic. **Scale trigger:** hot group → partition delivery/read fanout, not message truth. **Never:** treat live sockets/presence as durable delivery proof.

## 07 News Feed
**Truth:** posts and follows. **Contract:** feed has bounded freshness; cursor is stable. **Flow:** post outbox → fanout projection; read hydrates references. **Hard part:** hybrid push/pull for celebrity accounts and privacy deletion repair. **Scale trigger:** fanout write amplification → pull celebrity timelines at read. **Never:** duplicate full post data into every feed as permanent truth.

## 08 Checkout
**Truth:** order, inventory reservation, and financial journal. **Contract:** checkout idempotency key yields one order outcome. **Flow:** local transaction creates pending order/hold/outbox → payment saga → guarded state transition. **Hard part:** late/duplicate callback and compensation release. **Scale trigger:** inventory hot SKU → serialized/partition-aware allocation policy. **Never:** hold DB locks while calling payment provider.

## 09 Search and Autocomplete
**Truth:** catalog; index is rebuildable projection. **Contract:** state freshness target and permission filtering. **Flow:** catalog change → idempotent indexer → versioned index; query uses filters/ranking. **Hard part:** deletion/reindex without search leak. **Scale trigger:** autocomplete QPS → prefix cache/debounce. **Never:** declare search immediately consistent without a synchronization design.

## 10 Seat Reservation
**Truth:** seat state in transactional DB. **Contract:** hold token owns a short expiry; confirm only current hold. **Flow:** admission token → conditional seat hold → payment → sold. **Hard part:** race between expiry, payment, and concurrent buyers. **Scale trigger:** hot event → virtual waiting room and partition by venue/section. **Never:** read seat availability from cache then write it later.

## 11 Web Crawler
**Truth:** URL crawl state, content object/hash, robots/politeness state. **Contract:** URL normalization/version and per-host schedule. **Flow:** discovery → dedupe → host frontier → fetch → extract. **Hard part:** host-level rate policy and canonicalization that does not lose pages. **Scale trigger:** URL frontier → host partitions and distributed dedupe. **Never:** use one global FIFO or ignore terms/robots.

## 12 Workflow Scheduler
**Truth:** durable workflow state/task/lease. **Contract:** workflow steps are idempotent; task completion requires valid lease/fencing. **Flow:** timer/schedule generates task → worker activity → guarded next state. **Hard part:** crash after external side effect before acknowledgement. **Scale trigger:** task volume → shard queues by workflow/tenant class. **Never:** claim exactly-once without idempotent activities.

## 13 Metrics Platform
**Truth:** accepted timestamped samples in durable time-series blocks. **Contract:** labels/quotas are validated at ingest; queries have range/cardinality limits. **Flow:** agent → ingest/WAL → compacted store → query/alert. **Hard part:** active-series cardinality protection. **Scale trigger:** ingest → partition by tenant/time/series; downsample old data. **Never:** use metrics as audit-grade billing truth.

## 14 Logging Platform
**Truth:** durable log chunks; index is derived. **Contract:** structured schema and retention/ACL policy. **Flow:** agent buffer → ingest → chunks/index → bounded search. **Hard part:** redaction before broad access and bounded disk backpressure. **Scale trigger:** query/index cost → time/tenant partition plus tiered retention. **Never:** synchronously block user requests on logging.

## 15 Drive
**Truth:** immutable object versions plus metadata/ACL graph. **Contract:** sync cursor and version conflict semantics. **Flow:** direct upload → metadata transaction/outbox → device change feed. **Hard part:** offline concurrent edit conflict and delete/restore lifecycle. **Scale trigger:** metadata listing/sync → indexed per-folder/per-user change log. **Never:** make object key a permission token.

## 16 Video on Demand
**Truth:** source/derivative metadata and objects. **Contract:** playback entitlement authorizes manifest; encode state is explicit. **Flow:** upload → transcode ladder → manifests/segments → CDN/player. **Hard part:** quality adaptation and asynchronous encode failure/retry. **Scale trigger:** global playback → CDN origin shielding and rendition optimization. **Never:** serve original through application servers for each viewer.

## 17 Payment Ledger
**Truth:** immutable balanced journal postings. **Contract:** idempotent transfer/provider reference; corrections are new postings. **Flow:** transaction posts debit/credit → balance projection/outbox → reconciliation. **Hard part:** strong available-funds check and external mismatch. **Scale trigger:** account posting throughput → partition with careful per-account serialization. **Never:** overwrite balance/history as the only financial record.

## 18 Distributed Cache
**Truth:** external source database; cache is disposable. **Contract:** client has short timeout and TTL/stale policy. **Flow:** consistent-hash route → node/replica → coalesced source fallback. **Hard part:** hot key, expiry herd, node-loss miss storm. **Scale trigger:** add virtual nodes/replicas/local cache. **Never:** make eviction/restart mean data loss of business truth.

## 19 Feature Flags
**Truth:** versioned audited flag configuration. **Contract:** SDK evaluates a locally cached snapshot and reports staleness. **Flow:** control-plane change → validated distribution → SDK poll/stream → local evaluation. **Hard part:** safe kill-switch default during stale config/control outage. **Scale trigger:** many SDKs → CDN/stream fanout and segmented snapshots. **Never:** add remote lookup to every request or let flags live forever.

## 20 Ride Dispatch
**Truth:** transactional trip/assignment; location index is ephemeral. **Contract:** offer lease plus conditional first acceptance. **Flow:** driver location stream → geo cells; rider request → candidates → atomic assignment → realtime updates. **Hard part:** late accept/disconnect and dense-cell hotspot. **Scale trigger:** cell subdivision/region dispatch partitions. **Never:** choose a driver from stale location without assignment guard.

## 21 Multi-Tenant API Gateway
**Truth:** identity/policy/config control plane; services remain truth for resource permissions. **Contract:** gateway verifies token, quota, deadline, route/version; backend re-authorizes. **Flow:** edge → policy/cache → gateway → isolated service/data path. **Hard part:** identity/config outage and tenant noisy-neighbor limits. **Scale trigger:** route/tenant traffic → distributed quota and partitioned policy/config distribution. **Never:** centralize all domain logic or trust caller-supplied tenant ID.

## 22 Unique ID Generator
**Truth:** the ID itself. It holds 41 bits of milliseconds from a custom epoch, 3 bits of datacenter, 12 bits of worker and 7 bits of sequence, and each process leases its worker ID from a coordination service. **Contract:** unique, 64-bit and k-sortable (ordered to within clock skew, not strictly monotonic); IDs travel as strings in JSON. **Flow:** lease a worker ID at startup → generate in-process under a `lastTs` guard → renew the lease off the hot path. **Hard part:** clock rollback (wait out small regressions, refuse and drain on large ones) and a process that keeps generating after its lease was lost or reused. **Scale trigger:** more servers than worker bits → switch to a pooled ID service that hands out batches; if 64 bits is not required → UUIDv7. **Never:** put the coordinator on the per-ID path, size worker bits from the classic 10-bit diagram, or promise strict global order.

## 23 Distributed Key-Value Store
**Truth:** replicated LSM storage on the key's preference list (`N` distinct physical nodes on a consistent-hash ring with virtual nodes). **Contract:** tunable `R`/`W` per request; `put` carries a version-vector context, and `get` may return concurrent siblings. **Flow:** any node coordinates → parallel writes to `N` replicas → ack at `W` → read at `R` and resolve versions → read repair, hinted handoff and Merkle anti-entropy converge the replicas. **Hard part:** conflicts under partitions, tombstones that must outlive the repair interval, and "survive two failures" needing three durable copies at ack time. **Scale trigger:** throughput or data outgrows one ring → add nodes (about 1/n of keys move), then split into cells behind a routing layer and erasure-code cold data. **Never:** claim `R + W > N` is linearizable or remove a node from the ring on mere suspicion.

## 24 Collaborative Document Editor
**Truth:** the per-document operation log keyed `(doc_id, revision)` plus periodic snapshots. **Contract:** edits apply locally at once; the server assigns revisions; `op_id` makes resends idempotent; permissions are checked on every op. **Flow:** gateway WebSocket → the document's single session-server owner (consistent hash plus lease) → transform against later ops → conditional append `revision = last + 1` → ack → broadcast. **Hard part:** OT convergence under concurrent edits, offline resync, and fencing a stale owner. **Scale trigger:** one hot document's fan-out → read-only viewers on a broadcast stream, section sharding or a CRDT; op-log volume → snapshot and compact. **Never:** broadcast before the durable append, let two servers accept edits for one doc, or persist cursors in the log.

## 25 Web Search Engine
**Truth:** fetched documents in durable storage; index shards are immutable, versioned builds from them. **Contract:** crawl politely per host; serving answers p99 < 300 ms from a slightly stale snapshot; removals take effect at serve time. **Flow:** frontier → fetch → URL and content dedup → document-sharded inverted index (base tier plus fresh tier) → root fans out to leaves → merge → second-stage ranking → snippets. **Hard part:** tail latency across thousands of leaves (hedging, a hard leaf deadline, partial results) and keeping crawl quality up (traps, near-duplicates). **Scale trigger:** shard count or QPS → a mixer tree, a small high-quality tier searched first, and a query-result cache. **Never:** shard by term, update shards in place, or wait for a rebuild to apply a takedown.

## 26 Nearby Places
**Truth:** the `Place` store sharded by `place_id`; the in-memory S2 cell index is derived. **Contract:** results are fast everywhere and may be a few minutes stale; writes are asynchronous. **Flow:** place update → moderation → store → change event → geo indexer; search → S2 covering of the circle → range scans of cell IDs → exact distance and category filter → ranking. **Hard part:** dense city centres (per-cell lists capped by static score, then a shrinking radius) and cell-boundary misses. **Scale trigger:** read QPS or regional peaks → shard the index geographically with more replicas in dense metros, and cache results by `(cell, radius bucket, category)`. **Never:** run a lat/lng bounding box on a B-tree, look up only the user's own geohash cell, or hash-shard the index by `place_id`.

## 27 Ad Click Aggregation
**Truth:** the immutable raw click log/archive. Streaming aggregates are provisional; billing is recomputed from the archive. **Contract:** dashboards are fresh within minutes and approximate; billing is exact, reproducible, and final after a close period. **Flow:** click server logs asynchronously and 302-redirects → log → stream job keyed by `ad_id` over event-time one-minute windows with a watermark → idempotent upsert of absolute counts per `(ad_id, window)`; hourly batch dedups globally, applies fraud decisions and writes billing. **Hard part:** late events, replay without double-counting, and invalid traffic. **Scale trigger:** a hot ad → salt the key and sum the sub-keys; alert when stream and batch diverge by more than ~0.5%. **Never:** write `count += n` to the sink, window on processing time, or block the redirect on the log.

## 28 Top-K Trending
**Truth:** the raw event stream (the batch job's exact counts are the check). Published lists are an approximate projection. **Contract:** an approximate but stable top K per (window, region, category), refreshed each minute; heavy hitters are never missed. **Flow:** abuse filter → partition by `item_id` → count-min sketch plus a candidate heap (about K × 10) per slice per minute → merge sketches cell by cell → sliding window (add the newest bucket, subtract the oldest) → trend score against a baseline → publish to a key-value store and CDN. **Hard part:** error near the cut-off and choosing a score that surfaces rising items, not the always-popular. **Scale trigger:** slice count × memory → smaller sketches for small slices, coarser old buckets, and slices kept only when requested. **Never:** keep exact per-item maps per slice, use a sketch without candidates, or filter abuse after counting.

## 29 Real-Time Leaderboard
**Truth:** a score database written idempotently by `match_id`; sorted sets are a rebuildable projection. **Contract:** top 100 and each player's own score are exact and fresh within seconds; long-tail rank may be approximate and is flagged. **Flow:** signed server result → validate → DB → outbox/CDC → global top-1,000 set, hash-sharded player sets and a score histogram. **Hard part:** tie-breaking encoded in the score with enough time bits, and a rank that stays cheap at 50K reads/s. **Scale trigger:** memory or blast radius of one set → shard players, keep only the top in one set, and estimate rank from cached cumulative histogram counts. **Never:** accept client-reported scores, make Redis the only copy, fan out to every shard for each rank read, or reset a season by rewriting scores.

## 30 LLM Assistant Feature
**Truth:** the user's mailbox and ACLs (checked at retrieval time) and the versioned prompt template/model config. The model output is disposable. **Contract:** a streamed answer with time to first token p95 < 1 s; token quotas per user and org; no dangerous capabilities by default. **Flow:** AI gateway (auth, enablement, quota) → orchestrator → permission-filtered retrieval → input guard → router → continuous-batching model pool → output guard and citation check → SSE. **Hard part:** GPU cost (prefill and KV-cache memory, not just output tokens) and prompt injection from email content. **Scale trigger:** GPU demand → prefix caching, context trimming, route most traffic to a smaller model, and a bounded queue that sheds low-priority work. **Never:** stuff whole mailboxes into the prompt, share a semantic cache across users, or keep decoding after the client disconnects.

## 31 Distributed Message Queue
**Truth:** the partitioned, replicated append-only log (RF 3, `min.insync.replicas = 2`); consumer offsets are committed state. **Contract:** `publish` acks only once the message is on replicas in at least 2 zones (`acks=all`); order is per key only; delivery is at-least-once, and exactly-once effect needs an idempotent sink; replay for 7 days. **Flow:** producer batches → partition leader → followers fetch → high watermark → ack; consumer polls up to the watermark → process → commit offset; retry-tier topics and a DLQ on top. **Hard part:** the partition count is a one-way door for keyed order, and a poison message blocks its partition. **Scale trigger:** consumer parallelism or disk → size partitions from the consumer bound; per-tenant byte and partition quotas; tiered storage. **Never:** promise exactly-once to an external system, commit before processing, or claim order across partitions.

## 32 Ranked Home Feed
**Truth:** the post store and the event/impression log; the candidate set, features and session snapshot are derived. **Contract:** always answers inside the deadline at some quality rung; hard filters are absolute; pages come from a stable session snapshot. **Flow:** parallel retrievers (in-network and out-of-network) with quotas → hard filters → data-local light ranker (about 3,000 → 300) → heavy multi-task ranker → diversity → snapshot → hydrate; impressions are logged with features at serve time. **Hard part:** a fixed latency budget against candidates × per-item cost, train/serve skew, and exploration for cold-start items. **Scale trigger:** ranker CPU or p99 → shrink stage counts, hedge, and degrade down a tested ladder. **Never:** score every candidate with the heavy model, sort the union by incomparable retriever scores, re-rank on every page, or log clicks without impressions.

## 33 Live Streaming and Comments
**Truth:** segments in the object store (DVR and VOD reuse them) and the durable comment log. The viewer's feed is a sampled projection. **Contract:** video arrives as identical cacheable segments within a latency tier (under 10 s, or under 3 s low-latency); chat is durable when stored, at-most-once when displayed, and shown in sync with the playhead. **Flow:** ingest → real-time transcode ladder → packager → shield → CDN → player; post → moderation → per-room sequencer → sampled feed → relay tree → gateways. **Hard part:** transcoding must keep real time or drop frames, and comment fan-out at 10M viewers. **Scale trigger:** a mega-stream → request collapsing and shield, multi-CDN with headroom, a brownout ladder; ladders only for streams with an audience. **Never:** deliver every comment to every viewer, show chat ahead of video, or run transcoders at full utilisation.

## 34 Maps Routing and ETA
**Truth:** a versioned road-graph build (topology) plus a separate metric version (edge weights from live probes, time-of-day profiles and free flow). **Contract:** each route names its `build_id` and `metric_version`; the ETA carries a range; no data falls back to the profile, never to free flow. **Flow:** snap endpoints (HMM map matching) → overlay search on the continent-scale shard group's in-RAM graph → alternatives → re-price time-dependently → ML residual correction; probes → privacy-thresholded estimator → metric customization every ~60 s. **Hard part:** live weights without redoing preprocessing (customizable overlay, not plain CH), stale or spoofed probes, and reroute storms. **Scale trigger:** route QPS or a closure storm → more replicas per group, and shed proactive checks before off-route reroutes. **Never:** run Dijkstra at continent scale, hash-shard the graph, or let ML replace the path.

## 35 Distributed Object Store
**Truth:** a strongly consistent metadata index (bucket, key, version → placement of data chunks) plus erasure-coded chunks on storage nodes. **Contract:** a PUT is visible only after all chunks are durable and the metadata commit succeeds; reads after writes are consistent; durability is a stated number of nines; LIST is paginated in key order. **Flow:** front end → write fragments to nodes in separate failure domains → commit metadata → ack; GET reads metadata, then any `k` of `k + m` fragments. **Hard part:** the durability math (correlated failures and repair time dominate) and repair that must outrun disk loss without starving foreground traffic. **Scale trigger:** metadata hot partitions and huge LISTs → range-partition the index by key prefix and split hot ranges; tier cold data to wider codes. **Never:** ack before the metadata commit, delete chunks before garbage collection confirms no version references them, or treat replication and erasure coding as free.

## 36 Content Delivery Network
**Truth:** the tenant origin and the control plane's signed config, certificate and purge-log snapshots. Edge caches are disposable. **Contract:** tenant-scoped cache keys; never share `private`, `no-store` or `Set-Cookie` responses; purge p99 about 5 s; the data plane serves from last-known-good state when the control plane is unreachable. **Flow:** anycast or DNS mapping → L4 balancer → TLS at the edge → key from the zone snapshot → rendezvous-hash owner in the POP → regional parent → shield with request collapsing → origin. **Hard part:** purge without enumerating objects (sequence-numbered purge log and lazy checks), hot objects, and cache-key poisoning. **Scale trigger:** origin load or hot objects → a shield tier, cache on second hit, and hot-object replication inside the POP. **Never:** put a control-plane call on the request path, push config globally in one step, or depend on purge for correctness.

## 37 Experimentation Platform
**Truth:** immutable, versioned experiment config with bucket reservations, plus the deduplicated exposure log. **Contract:** assignment is a pure local function `f(config_version, unit_id)` (p99 < 1 ms, stable while the experiment runs); config reaches all servers within 60 s; readouts are gated on an SRM check and sequential tests. **Flow:** create (power check, reserve buckets, audit) → signed snapshot distribution → hash layer salt for the experiment and experiment salt for the variant → log exposure where the parameter is used → stream guardrails plus batch readout. **Hard part:** sample-ratio mismatch, peeking, late data, and interference (cluster randomization). **Scale trigger:** too many experiments for the traffic → more layers, CUPED variance reduction, and smaller default allocations. **Never:** log exposure at assignment or only for treatment, read results before the SRM check, or call a remote assignment service per request.

## 38 Video Conferencing
**Truth:** meeting metadata, recordings and transcripts. SFU media state is soft, and clients rebuild it. **Contract:** media is best-effort with a deadline (audio outranks video); control is reliable, ordered and idempotent per meeting; media is forwarded, never re-encoded, on the live path. **Flow:** signaling (SDP, ICE) → placer picks the room's SFU → simulcast layers up → per-receiver layer selection and last-N → cascade links to edge SFUs in other regions. **Hard part:** bandwidth estimation on both legs, loss repair inside the jitter budget (NACK or FEC), and the latency of cross-region cascades. **Scale trigger:** node egress or remote joiners → place by egress headroom, cascade SFUs, and switch giant meetings to view-only fan-out. **Never:** use mesh beyond about 4 people, default to an MCU, forward every stream to everyone, or let the sender pick quality.

## 39 Social Graph Service
**Truth:** `id1`-sharded MySQL holding objects, typed associations and counts; follower and leader cache tiers are derived. **Contract:** eventually consistent for others (about a second), read-your-writes for the actor via a version token, both edge directions converge through an outbox, privacy checked at read time. **Flow:** write → shard leader transaction (edge + count + outbox row for the inverse) → invalidate or refill followers; read → follower cache → leader on a miss → one DB query. **Hard part:** hot celebrity lists and objects, lost invalidations, and the non-atomic inverse edge. **Scale trigger:** read QPS → a hit ratio held near 99% with shard cloning and client caches; a cold region is warmed by replaying hot keys before it takes traffic. **Never:** partition the graph by region or community, use `COUNT(*)` or offset paging, or enforce privacy at fanout time.

## 40 Distributed Lock Service
**Truth:** a 5-replica consensus log (Raft or Multi-Paxos) holding the node tree, locks and sessions. **Contract:** at most one exclusive holder; each grant returns a monotonically increasing fencing token (the commit index); sessions survive a failover inside the grace period; writes are linearizable. **Flow:** client library KeepAlive → master lease; acquire → commit → sequencer; the resource checks the token atomically with the write; watches and invalidations keep client caches coherent. **Hard part:** the paused holder (only the resource can reject it), jeopardy versus expiry after failover, and the waiter herd. **Scale trigger:** sessions and read load → proxies, then observers, then more cells by namespace; per-tenant write and watch quotas. **Never:** hand out a TTL lock without fencing, run KeepAlives through consensus, or use the service as a database or queue.

## 41 Email Service
**Truth:** per-user mailbox storage (message bodies in a blob store, plus a per-mailbox metadata log of message, label and flag changes with a monotonically increasing modification sequence). **Contract:** reply `250` to SMTP only after the message is durably stored (at least two copies); delivery is at-least-once and deduplicated by Message-ID per mailbox; clients sync from a cursor; search covers only the user's own mail. **Flow:** MX → SMTP ingest (SPF/DKIM/DMARC, rate limits) → durable queue → spam and malware pipeline → mailbox write plus change event → per-user search index and push notifications; outbound → queue → per-destination-domain delivery with retries and bounces. **Hard part:** spam at scale without losing legitimate mail, and outbound deliverability (IP and domain reputation, per-domain throttling). **Scale trigger:** mailbox count and storage → shard by user, keep the index per user, and tier old mail to cold storage; a spam spike → cheap reputation rules first, expensive models second. **Never:** accept (`250`) before the durable write, share one search index across users without per-user filtering, or send bulk mail from the transactional IP pool.

## How to use each blueprint

Before reviewing a solution, replace each bold label with your own answer. Then force one changed condition: strict multi-region consistency, 100× traffic, no cache, a dependency outage, or regulated data. If your architecture still has a precise source of truth, idempotent mutations, bounded failure, and evidence, you are learning system design rather than reciting it.
