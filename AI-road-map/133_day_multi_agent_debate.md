Welcome to Day 133. 

Single Agents suffer from terrible confirmation bias. If an Agent accidentally hallucinates a fake fact on Step 1 of its plan, it will blindly defend and build upon that hallucination all the way to Step 10.
How do humans solve confirmation bias in the real world? We debate. We bring in peer reviewers.

Today, we apply Marvin Minsky's "Society of Mind" theory to <abbr title="Artificial Intelligence">AI</abbr>. We will force multiple <abbr title="Artificial Intelligence">AI</abbr> models to argue with each other until they converge on the mathematical truth!

## 🕒 HOUR 1: DEEP THEORY & ANALOGIES

### 1. Multi-Agent Debate
Instead of one Agent solving a problem, we instantiate three Agents:
- **Agent A (The Proposer):** Argues that the answer is "Yes".
- **Agent B (The Opposer):** Argues that the answer is "No".
- **Agent C (The Judge):** Reads the transcript of the debate. It ignores the rhetoric and strictly evaluates the factual evidence presented by A and B to declare a winner.
This architecture drastically reduces hallucinations because Agent B will aggressively attack any fake facts generated by Agent A!

### 2. Consensus Algorithms
When 5 specialized agents are analyzing a stock, they might disagree. How does the system make a final decision?
- **Majority Voting:** The simplest method. Run 5 independent agents in parallel. If 3 say "Buy" and 2 say "Sell", the system outputs "Buy".
- **Confidence-Weighted Voting:** The Agents must output a confidence score (e.g., `{"decision": "Sell", "confidence": 95}`). The Judge mathematically weighs the votes. An Agent who is $95\%$ sure overrides three Agents who are only $51\%$ sure.

### 3. Collaboration Patterns
When Agents aren't debating, they are collaborating. How do they communicate?
- **Hub-and-Spoke:** A central "Manager" Agent talks to the Data Agent, gets the result, and passes it to the Writer Agent. The Data and Writer agents never speak directly.
- **Peer-to-Peer:** Agents talk directly to each other via a shared message bus. The Architect designs the code and sends a direct Slack-like message to the Developer Agent to write it.

## 🕒 HOUR 2: GUIDED CODE-ALONG (THE APPLIED WAY)

Let's build a Multi-Agent Debate System! We will pit a Proposer against an Opposer for 2 rounds, and then have a Judge render a final verdict.

Create a file named `multi_agent_debate.py`:

```python
def mock_llm_proposer(history):
    print("\n[PROPOSER] Speaking...")
    if len(history) == 1:
        return "Electric vehicles (EVs) are the future. They produce zero emissions and save money on gas."
    return "The Opposer is wrong. Battery recycling is improving, making EVs vastly superior long-term."

def mock_llm_opposer(history):
    print("\n[OPPOSER] Speaking...")
    return "EVs are terrible for the environment. The lithium mining process destroys local ecosystems and requires massive fossil fuels."

def mock_llm_judge(history):
    print("\n[JUDGE] Reviewing the transcript and making a final ruling...")
    return "FINAL VERDICT: Both sides present valid points. The Proposer wins on long-term emissions, but the Opposer correctly highlights the short-term mining impact. The truth is highly dependent on the local energy grid."

def run_debate_simulation():
    print("--- RUNNING MULTI-AGENT DEBATE ---\n")
    
    topic = "Are Electric Vehicles actually good for the environment?"
    print(f"DEBATE TOPIC: {topic}\n")
    
    # The shared memory (The Debate Transcript)
    transcript = [f"TOPIC: {topic}"]
    
    num_rounds = 2
    for round_num in range(num_rounds):
        print(f"--- ROUND {round_num + 1} ---")
        
        # 1. Proposer speaks
        proposer_statement = mock_llm_proposer(transcript)
        print(f"PROPOSER: {proposer_statement}")
        transcript.append(f"PROPOSER: {proposer_statement}")
        
        # 2. Opposer speaks (reads the Proposer's exact statement!)
        opposer_statement = mock_llm_opposer(transcript)
        print(f"OPPOSER: {opposer_statement}")
        transcript.append(f"OPPOSER: {opposer_statement}")
        
    print("\n--- DEBATE CONCLUDED. ENTERING JUDGMENT PHASE ---")
    
    # 3. The Judge reads the entire transcript!
    final_verdict = mock_llm_judge(transcript)
    print(f"\n{final_verdict}")

if __name__ == "__main__":
    run_debate_simulation()
```

### Key Takeaways from Code:
1. **Adversarial Accuracy:** By forcing the Opposer to read the Proposer's exact text, the Opposer's attention mechanism is mathematically forced to look for logical flaws. This adversarial setup mimics GANs (Day 57) but for text logic!
2. **The Shared Transcript:** In Peer-to-Peer agent communication, the `transcript` array acts as a "Blackboard". It is a shared state vector that all agents can read from and append to.
