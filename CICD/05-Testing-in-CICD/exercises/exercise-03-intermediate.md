# Exercise 03: Testing Go HTTP Handlers with Mocks 🟡

## 🎯 Objective
Test an HTTP handler in Go using `httptest` and interface-based mocking to isolate the handler from a real database.

## 📋 Prerequisites
- Go installed.

## 📝 Instructions

1. Define a `UserService` interface and an HTTP handler that fetches user data.
2. Create a mock implementation of the `UserService`.
3. Use `httptest.NewRecorder()` to simulate HTTP requests to your handler.

### Step 1: Write the Application Code
Create `main.go`:

```go
package main

import (
	"encoding/json"
	"net/http"
)

// User represents our data model
type User struct {
	ID   string `json:"id"`
	Name string `json:"name"`
}

// UserService defines how we fetch user data (abstracts the DB)
type UserService interface {
	GetUserByID(id string) (*User, error)
}

// UserHandler holds our dependencies
type UserHandler struct {
	Service UserService
}

// HandleGetUser handles GET requests for users
func (h *UserHandler) HandleGetUser(w http.ResponseWriter, r *http.Request) {
	// In a real app, you'd extract the ID from the URL path. Hardcoded for simplicity.
	id := r.URL.Query().Get("id")
	if id == "" {
		http.Error(w, "missing user id", http.StatusBadRequest)
		return
	}

	user, err := h.Service.GetUserByID(id)
	if err != nil {
		http.Error(w, "user not found", http.StatusNotFound)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(user)
}
```

### Step 2: Write the Test Code with Mocks
Create `main_test.go`:

```go
package main

import (
	"errors"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

// MockUserService implements UserService for testing
type MockUserService struct {
	mockGetUserByID func(id string) (*User, error)
}

func (m *MockUserService) GetUserByID(id string) (*User, error) {
	return m.mockGetUserByID(id)
}

func TestHandleGetUser(t *testing.T) {
	// Set up the mock to return a specific user
	mockService := &MockUserService{
		mockGetUserByID: func(id string) (*User, error) {
			if id == "123" {
				return &User{ID: "123", Name: "Jane Doe"}, nil
			}
			return nil, errors.New("not found")
		},
	}

	// Inject the mock into the handler
	handler := &UserHandler{Service: mockService}

	t.Run("Success", func(t *testing.T) {
		req, _ := http.NewRequest("GET", "/user?id=123", nil)
		rr := httptest.NewRecorder()

		handler.HandleGetUser(rr, req)

		if status := rr.Code; status != http.StatusOK {
			t.Errorf("expected %v, got %v", http.StatusOK, status)
		}

		expected := `{"id":"123","name":"Jane Doe"}`
		if strings.TrimSpace(rr.Body.String()) != expected {
			t.Errorf("expected body %v, got %v", expected, rr.Body.String())
		}
	})

	t.Run("Missing ID", func(t *testing.T) {
		req, _ := http.NewRequest("GET", "/user", nil)
		rr := httptest.NewRecorder()

		handler.HandleGetUser(rr, req)

		if status := rr.Code; status != http.StatusBadRequest {
			t.Errorf("expected %v, got %v", http.StatusBadRequest, status)
		}
	})

	t.Run("Not Found", func(t *testing.T) {
		req, _ := http.NewRequest("GET", "/user?id=999", nil)
		rr := httptest.NewRecorder()

		handler.HandleGetUser(rr, req)

		if status := rr.Code; status != http.StatusNotFound {
			t.Errorf("expected %v, got %v", http.StatusNotFound, status)
		}
	})
}
```

### Step 3: Run the Tests
```bash
go test -v .
```

## 💡 Hints
- `httptest.NewRecorder()` captures the HTTP response generated by the handler, allowing you to inspect status codes, headers, and the response body.
- By defining `UserService` as an interface, the HTTP handler has no idea it's talking to a mock instead of a real database.

## 🧠 Key Takeaway
Testing HTTP handlers doesn't require spinning up an actual web server or database. By using interfaces and `httptest`, you can write incredibly fast, isolated tests for your API endpoints.
